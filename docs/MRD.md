# MRD：量化自进化信号系统

> 版本: v1 (2026-09-10)
> 状态: 设计中

---

## 一、背景与问题

**原系统**：LLM 写策略预测"2 天涨 3%"，实测命中率 0%，回测与实盘脱节。

**根本原因**（经 8.5 年数据验证）：
1. "2 天方向预测"是低 SNR 死路（信噪比太低）
2. 池子真实有效的是**截面信号**（反转/动量/行为因子）
3. 信号本质是**可预测的集体行为偏差**，会随机构化/套利而衰减

## 二、目标

1. **自进化**：持续"发现 → 验证 → 上线 → 淘汰"信号，在衰减前换新
2. **解耦**：信号生成（研究）与线上预测（生产）两套系统，物理隔离
3. **可验证**：infra 有效性是验证任何 idea 的前提（infra 不牢，一切 idea 无法证伪）

## 三、用户与使用场景

| 角色 | 场景 | 频率 |
|------|------|------|
| 研究者（我） | 观察信号状态、手动晋升/淘汰、看 dashboard | 随时 |
| 系统（自动） | 每日预测、每日找信号、每日监控 | 自动 |

## 四、核心需求（R1-R7）

### R1 数据层
- 拉取不复权 raw + 送转因子（point-in-time 复权）
- 交易日历 + 完整性校验 + 审计日志
- 增量更新（并发，避免重复拉取）

### R2 信号生成系统 A（研究侧）
- LLM 提因子假设 + 五闸门确定性验证（LLM 不打分）
- 候选信号写入注册表（proposed 状态）
- 可每日运行

### R3 线上预测系统 B（生产侧）
- 读注册表中的 **active 信号**（非硬编码）
- 多信号并行预测 + 分仓组合（主仓 regime 门控 + 卫星仓正交信号）
- 生成每日推荐并持久化

### R4 信号生命周期
- 状态机：proposed → validated → paper → active → decayed → retired
- 衰减监控（滚 IC）+ 自动退役

### R5 监控
- 5 大类：服务健康 / 数据拉取 / LLM 成功率 / 预测效果 / 其他
- 回测 vs 实盘偏差检测 + 效果日志收集

### R6 Dashboard
- 可视化：信号生成状态、上线预测状态、系统健康、数据状态

### R7 编排器（上帝服务）
- 统一入口，调度 daily / evolve / monitor / promote / retire / status
- 轻量，只做"调度 + 状态管理 + 异常处理"，具体逻辑留在各模块

## 五、架构

```
              ┌────────── supervisor.py (编排器) ──────────┐
              │   daily / evolve / monitor / promote /    │
              │   retire / status                          │
              └────┬───────────┬─────────────┬────────────┘
                   │           │             │
        ┌──────────▼─────┐ ┌───▼─────────┐ ┌─▼────────────┐
        │ 系统A 信号生成   │ │ 系统B 线上预测│ │ 数据层        │
        │ signal_evolve  │ │ live_strategy│ │ data_fetch    │
        │ (LLM+五闸门)    │ │ (读active信号)│ │ build_data    │
        └────────────────┘ └──────────────┘ └──────────────┘
                   │           │
                   └─────┬─────┘
                  ┌──────▼──────┐
                  │ 信号注册表    │ (JSON: proposed/active/decayed)
                  └─────────────┘
```

**设计原则**：
1. 进化（A）与线上（B）解耦，A 出问题污染不到 B
2. 编排器轻量，模块职责单一
3. 失败安全默认（数据脏了宁可不出信号）

## 六、非功能性需求

- **确定性**：相同输入相同输出，可复现
- **可回滚**：信号退役只移出 active，不删代码
- **可观测**：所有状态可查询（status/dashboard）
- **成本可控**：LLM 调用有预算（每日 N 次）
